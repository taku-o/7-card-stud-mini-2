# Requirements Document

## Project Description (Input)
7スタッドポーカーのWebアプリを作成します。人間対CPUの1対1の仕組みで、tipなどの機能は不要です。仕様の詳細はお任せします。どのように作るかは任せます。

## Requirements

### Requirement 1: 基本ゲームルールとターン進行
**Objective:** プレイヤーとして、7カードスタッドポーカーの基本ルールに従ってゲームを進行できるようにしたい。そうすることで、実際のカードゲームに近い体験ができる。

#### Acceptance Criteria
1. システムは1ゲームにおいて、プレイヤーとCPUそれぞれに7スタッドポーカーのルールに従ったカード配布（ホールカードとアップカード）を行わなければならない。
2. システムは各ストリートごとにベッティングフェーズを用意し、プレイヤー→CPUの順序でアクションが進行するようにしなければならない。
3. システムは全てのストリートが終了した後にショーダウンを実行し、役の強さ比較により勝敗を自動判定しなければならない。
4. システムはゲームの進行中、現在のストリート、残りカード枚数、ベット状況を画面上に表示し続けなければならない。
5. システムはラウンド終了時に、勝者、役の内容、獲得・喪失したチップ数を表示しなければならない。

### Requirement 2: プレイヤー操作とベッティング
**Objective:** プレイヤーとして、自分の意思でベット/コール/フォールドなどのアクションを直感的に選択できるようにしたい。そうすることで、戦略的なプレイが可能になる。

#### Acceptance Criteria
1. システムは各ベッティングフェーズで、プレイヤーに対して少なくとも「ベット（またはレイズ）」「コール」「フォールド」のアクションボタンを表示しなければならない。
2. システムはプレイヤーが選択可能なアクションのみを能動的に表示し、選択不可能なアクションは非活性または非表示にしなければならない。
3. システムはプレイヤーがアクションを選択した際、その結果としてのチップ増減とポットの合計額を即時に反映しなければならない。
4. システムはプレイヤーの現在スタック（保有チップ数）とポットサイズを常に画面上に表示しなければならない。
5. システムはプレイヤーがフォールドを選択した場合、その時点でラウンドを終了させ、勝者としてCPUとその理由（フォールド勝ち）を表示しなければならない。

### Requirement 3: CPUプレイヤーの思考と挙動
**Objective:** プレイヤーとして、人間と対戦している感覚を得られる程度のCPU挙動が欲しい。そうすることで、1対1でも飽きにくい対戦体験を得られる。

#### Acceptance Criteria
1. システムはCPUのアクションを、少なくとも「常に同じ行動を取る」単純なランダムではなく、手札の強さとボード状況に応じて変化するロジックに基づいて決定しなければならない。
2. システムはCPUの思考処理中であることを示すインジケータ（例: 「CPU思考中…」）を一定時間表示し、その後にアクション結果を表示しなければならない。
3. システムはCPUの決定したアクション内容（ベット、コール、フォールドなど）と、その結果のポット・スタック変化をプレイヤーに視覚的に分かる形で表示しなければならない。
4. システムはCPUのプレイスタイル（例: タイト/ルースなど）をソースコード上で切り替え可能な構造とし、単体テストでパラメータを変えたときに挙動の差異を確認できなければならない。
5. システムはCPUが全ストリートを通じて常にコールする、あるいは常にフォールドする、といった極端な挙動に固定されないようチューニングされていなければならない。

### Requirement 4: ゲームセッション管理とUI
**Objective:** プレイヤーとして、ブラウザ上でストレスなく複数ラウンドを連続プレイできるようにしたい。そうすることで、学習や娯楽目的で長く遊べる。

#### Acceptance Criteria
1. システムはブラウザ上で動作し、新規ゲーム開始・ラウンドの自動遷移・次のラウンド開始をすべて単一ページ内で行えるUIを提供しなければならない。
2. システムはゲーム開始時にプレイヤーの初期チップ数を設定し、各ラウンド終了後もそのチップ数を引き継いで次ラウンドに進行しなければならない。
3. システムは現在までのゲーム数、勝利数、敗北数、勝率（簡易な統計でよい）を画面上の情報パネルで確認できるようにしなければならない。
4. システムはブラウザのリロード時にゲーム状態がリセットされる前提とし、その旨をUI上の説明テキストで明示しなければならない（永続化は必須要件としない）。
5. システムはtip機能や課金・広告など、本要件に含まれない付加機能をUI上に表示してはならない。
