# Implementation Plan

- [ ] 1. ゲームドメイン基盤の実装
- [ ] 1.1 デッキ・カード・手札ドメインモデルの実装
  - `Card`（スート・ランク）、デッキ初期化・シャッフル機能を実装する。
  - プレイヤー/CPU の 7 枚手札 (`Hand`) を表現する構造を実装する。
  - _Requirements: 1_
- [ ] 1.2 HandEvaluator（役判定ロジック）の実装
  - 7 枚から最強 5 枚を選択し、役種と強さを比較可能な形式で返すロジックを実装する。
  - 代表的な役パターン（ハイカード〜フルハウス/フォーオブアカインドなど）についてテストケースを用意する。
  - _Requirements: 1_
- [ ] 1.3 GameState 構造体とストリート遷移管理の実装
  - ポット、スタック、現在ストリート、配布カード、ラウンド結果を保持する `GameState` を定義する。
  - 7 カードスタッドの各ストリート進行（カード追加・ストリート更新）を表現できる状態遷移ロジックを実装する。
  - _Requirements: 1, 2_

- [ ] 2. GameEngine サービスの実装
- [ ] 2.1 ラウンド開始とカード配布処理の実装
  - `startNewRound` 相当のメソッドでデッキ初期化・アンティ/ブリングインの反映（必要に応じて簡易化）・初期カード配布を行う。
  - 初期状態の `GameState` を返却し、UI が表示できる形にする。
  - _Requirements: 1_
- [ ] 2.2 プレイヤーアクション処理とポット更新の実装
  - `playerAction` 相当のメソッドでベット/コール/フォールドを受け取り、スタックとポットを更新する。
  - フォールド時にはただちにラウンド終了状態に遷移する。
  - _Requirements: 2_
- [ ] 2.3 CPU アクション連携とストリート進行の実装
  - プレイヤーアクション後に CpuStrategy を呼び出し、CPU のアクションを決定する。
  - ストリート終了条件を満たしたら次ストリートへ自動遷移し、必要なカードを配布する。
  - _Requirements: 1, 2, 3_
- [ ] 2.4 ショーダウンとラウンド結果判定の実装
  - 最終ストリート終了後に HandEvaluator による役判定を行い、勝者とチップ変動を決定する。
  - `RoundResult` を生成し、GameState に格納する。
  - _Requirements: 1, 4_

- [ ] 3. CpuStrategy モジュールの実装
- [ ] 3.1 戦略パラメータとインタフェース定義
  - タイト/ルース、アグレッシブ/パッシブなどのパラメータを持つ `CpuStrategyOptions` を定義する。
  - `decideAction(state, options)` インタフェースを確定する。
  - _Requirements: 3_
- [ ] 3.2 手札・ボード状況に応じたアクション決定ロジックの実装
  - ハンド強さとストリートに応じて、ベット/コール/フォールド確率を変化させる簡易ロジックを実装する。
  - ランダム性を加えつつ、常に同じ行動にならないよう調整する。
  - _Requirements: 3_
- [ ] 3.3 CPU 挙動のテスト実装
  - 強い手・弱い手など代表的な状態を用意し、決定されるアクション傾向をテストで確認できるようにする。
  - パラメータを変えたときに挙動が変化することをテストする。
  - _Requirements: 3_

- [ ] 4. UI 実装（GameView）
- [ ] 4.1 ゲーム画面レイアウトの実装
  - カード表示領域、ポット・スタック表示、アクションボタン、統計パネルを含むレイアウトを実装する。
  - tip/課金など本要件外の UI 要素を含めないことを確認する。
  - _Requirements: 1, 2, 4_
- [ ] 4.2 アクションボタンと状態反映の実装
  - ベット/コール/フォールドなどのボタンを実装し、利用可能なアクションのみ活性状態にする。
  - ボタンクリックで GameEngine を呼び出し、返却された GameState を画面に反映する。
  - _Requirements: 2_
- [ ] 4.3 ゲーム進行・結果表示・リセット文言の実装
  - 現在ストリート、残りカード、ベット状況、勝者・役の内容・チップ変動を UI に表示する。
  - ブラウザリロード時にゲーム状態がリセットされる前提であることを画面上のテキストで明示する。
  - _Requirements: 1, 4_

- [ ] 5. 統計管理（StatsTracker）の実装
- [ ] 5.1 ラウンド結果の集計ロジック実装
  - ラウンド終了時に勝敗・チップ変動を記録し、ゲーム数/勝利数/敗北数/勝率を計算する。
  - ブラウザリロード時には統計が初期化される前提で実装する。
  - _Requirements: 4_
- [ ] 5.2 統計情報表示 UI の実装
  - GameView 内に統計パネルを配置し、現在の統計値を表示する。
  - ラウンド終了ごとに最新統計を反映する。
  - _Requirements: 4_

- [ ] 6. テスト実装
- [ ] 6.1 ドメイン層ユニットテストの実装
  - HandEvaluator の役判定と比較テストを複数パターン用意する。
  - GameEngine のストリート遷移・ポット更新ロジックのテストを実装する。
  - _Requirements: 1, 2_
- [ ] 6.2 CpuStrategy ユニットテストの実装
  - 代表的な GameState パターンに対するアクション傾向のテストを実装する。
  - 戦略パラメータ変更時の挙動差異を検証するテストを追加する。
  - _Requirements: 3_
- [ ] 6.3 統合テスト・E2E テストの実装
  - GameEngine と CpuStrategy を組み合わせて 1 ラウンドが正しく進行する統合テストを実装する。
  - ブラウザ上で「新規ゲーム→1 ラウンド終了→結果表示」までの E2E テストを実装する。
  - _Requirements: 1, 2, 3, 4_
